## Bounded cycle correction

The single-target helper delegates to a bounded batch helper. It captures target UUIDs and the originating repo/worker once, deduplicates in order with a hash table, reads current block statuses once, resolves closed values on that same repo, and submits one operation batch with `outliner-op=cycle-todos`. The existing Outliner_ops boundary retains save/refresh/history ownership. No new dispatcher, state registry, scheduler, compatibility shim or UI queue is added.

The shared scenario is compiled for both actual Web and native adapters. It dispatches the real CmdK ID, then the real Popups_state context-menu command through the installed document adapter. Its stateful fake worker applies status writes and serves them on the next read. Cases cover nonediting multiselection/document order, editing fallback, repeated fresh-state cycling, dirty-editor identity, selected-context and outside-selection targeting, one transaction, and graph retirement before mutation. The low-level honest-unimplemented scenario is unchanged. The actual native runner extracts the explicitly marked portable TEST fixture from the maintained shared view regression file and recompiles that exact function against the actual native archives. The production Cmdk_host, Editor_commands and Popups_state implementations are loaded from their actual target archives; they are not copied into the fixture. The Web suite compiles the same fixture normally. No Dune file changes are required.

These are source regressions awaiting root execution. A passing fake worker proves command routes, captured targets and operation shape, not physical status UI paint, native Mod-Enter delivery or a real SQLite undo history. Those require an actual release app test with current artifact receipts and an owned graph. This candidate is not completion of the remaining context-menu or plugin gaps above.
